# Rustym v0.0.3

This release fixes the packaging reliability problems that could leave installs
unable to play music, bundles the streaming toolchain inside the app's packages,
and adds a built-in way to keep those tools up to date — plus a proper automated
release pipeline.

## 🎵 Bundled streaming stack — no more "old yt-dlp" breakage

- Every package (`.deb`, `.rpm`, `.pkg.tar.zst`) now ships current copies of
  **yt-dlp and deno** in `/usr/lib/rustym/`, pinned at build time instead of
  depending on whatever the distro ships.
- Distro yt-dlp is often years old and causes the "Please sign in" errors, HTTP
  403s from Google's CDN, and endless skip/auto-advance behaviour reported on
  Ubuntu. Bundled copies are used **before** the system ones automatically — no
  configuration needed.
- `yt-dlp` and `deno` are no longer distro dependencies of the package; only
  mpv, ffmpeg and the desktop libraries remain.

## 🛠️ Settings → Dependencies (in-app updater)

- New **Dependencies** card in Settings › General shows yt-dlp, deno, mpv and
  ffmpeg with detected version, path and OK/missing status at a glance.
- One-click **"Update yt-dlp & deno"**: downloads the newest releases into
  `~/.local/bin` — no root, no commands, works the same on Arch, Debian/Ubuntu
  and Fedora. User-updated copies always win over both the bundled and system
  ones.
- The old `yt-dlp -U` maintenance button was replaced by this (it could never
  work with distro-owned or bundled copies).

## 📦 Packaging & CI fixes

- Fixed the Arch CI job failing on tag builds: `PKGBUILD` source/checksum
  rewriting is now multi-line-safe and reproducible against the actually pushed
  tag.
- Fixed the branch-build source tarball generation (`tar` aborted with *"file
  changed as we read it"* when the tarball grew inside the tree being archived).
- The release job no longer fails when a release was created manually before
  the tag build finished: it now replaces the assets instead of erroring.
- Version is now kept consistent everywhere (Cargo.toml, Cargo.lock, PKGBUILD),
  so package metadata always matches the release tag.

## 🚀 Automated releases

- New **Release** workflow: running it with a version number bumps the version
  files, pushes the tag, builds all three packages, and publishes the GitHub
  release with notes and all packages attached. Releasing is now a single
  version input, not a manual checklist.

## ⬆️ Upgrading

Install as usual (`.deb`, `.rpm` or `pacman -U`). After upgrading, Rustym
automatically prefers the bundled yt-dlp/deno; existing `cookies.txt`,
playlists, liked songs and settings are untouched.
